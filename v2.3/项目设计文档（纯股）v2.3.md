# QMT 模拟盘 Pipeline — 项目设计文档（纯股）v2.3

**版本**：v2.3
**日期**：2026-05-04
**状态**：开发中
**范围**：股票 + ETF + 指数 + 财务 + 分红 + 宏观，基于 v2.2 扩展

---

## 与 v2.1 的主要变化

| 变化点 | v2.1 设计 | v2.3 设计 | 原因 |
|--------|-----------|---------|------|
| 数据采集范围 | 仅日线 OHLCV（股票+指数+ETF） | 日线 + 财务(7表) + 分红 + 品种元数据 + 指数权重 + ETF申赎 + 宏观 | 为新策略探索提供完整数据源 |
| 宏观数据 | 无 | AKShare（GDP/CPI/PMI/M2/LPR/社融等 30+ 指标） | QMT 不提供宏观数据 |
| 存储格式 | Parquet（服务器端） | Parquet（本地端，与服务器相同规范） | 本地也需高效读取历史序列 |
| 数据更新策略 | 每日全量推送 | 增量更新（按标的追加行，按日期去重） | 避免重复下载历史数据 |
| 配置文件 | config.py 单文件 | config.py + collectors.yaml（采集清单） | 解耦数据采集和业务逻辑 |
| 新增模块 | — | `data_collector.py`（统一采集引擎） | 所有数据采集集中管理 |

继承自 v2.1/2.2 的核心设计（多账户、信号归集、虚拟资金隔离、交易执行）全部保留。

---

## 项目目标

本版本在 v2.2 的 pipeline 基础上，新增一套完整的**本地数据采集系统**：

- **QMT 数据**：日线 OHLCV、财务 7 表、分红送配、品种元数据、指数权重、ETF PC
- **宏观数据**：通过 AKShare 采集 GDP、CPI、PMI、M2、LPR、社融等 30+ 核心指标
- **统一存储**：所有数据以 Parquet 格式存入 `data/` 目录，按标的或指标分文件
- **增量更新**：已有数据不重复下载，仅追加新数据
- **离线可用**：策略探索时不依赖 QMT 实时连接或服务器

## 数据存储设计

### Parquet 通用规范

- **编码**：字符串字段使用 `pyarrow.string()`，日期使用 `int32`（YYYYMMDD）
- **排序**：每个 Parquet 文件按时间列升序存储
- **去重**：写入前检查主键是否已存在，已存在则跳过
- **引擎**：`pyarrow` 或 `fastparquet`（优先 pyarrow）
- **压缩**：snappy（默认，平衡速度与大小）

### 追加写入模式

```python
def append_to_parquet(filepath: str, new_df: pd.DataFrame, pk_col: str) -> int:
    """追加写入 Parquet，按主键去重。返回新增行数。"""
    if os.path.exists(filepath):
        existing = pd.read_parquet(filepath)
        existing_pks = set(existing[pk_col])
        new_rows = new_df[~new_df[pk_col].isin(existing_pks)]
        if new_rows.empty:
            return 0
        merged = pd.concat([existing, new_rows], ignore_index=True)
        merged.sort_values(pk_col, inplace=True)
    else:
        new_rows = new_df.copy()
        merged = new_rows.sort_values(pk_col)
    merged.to_parquet(filepath, index=False)
    return len(new_rows)
```

## 采集引擎设计（data_collector.py）

### 配置驱动

采集任务在 `collectors.yaml` 中声明：

```yaml
# 采集频率定义
frequencies:
  daily:     # 每个交易日运行
    - market_ohlcv      # 日线行情
    - index_weights      # 指数权重
    - macro_lpr          # LPR
    - macro_shibor       # Shibor
    - macro_margin       # 融资融券
  weekly:    # 每周运行（交易日）
    - dividends          # 分红送配
    - macro_weekly       # 周度宏观
  monthly:   # 每月第一个交易日运行
    - instruments        # 品种元数据快照
    - financial_tables   # 财务数据增量
    - macro_monthly      # 月度宏观
  quarterly: # 季报窗口期运行
    - financial_full_refresh  # 财务数据全量刷新
```

### 数据采集注册表

```python
COLLECTORS = {
    "market_ohlcv":         MarketOHLCVCollector,
    "financial_tables":     FinancialTablesCollector,
    "dividends":            DividendCollector,
    "instruments":          InstrumentCollector,
    "index_weights":        IndexWeightCollector,
    "etf_pc":               ETFPCCollector,
    "macro_china":          MacroChinaCollector,
    "macro_global":         MacroGlobalCollector,
}
```

### 运行模式

```bash
# 全量采集（首次使用）
python data_collector.py --full

# 按频率采集
python data_collector.py --freq daily
python data_collector.py --freq weekly
python data_collector.py --freq monthly

# 采集指定类型
python data_collector.py --type financial_tables,dividends

# 仅预览（不写入）
python data_collector.py --type macro_china --dry-run
```

排序键：`date`

## 与 v2.2 pipeline 的集成

v2.3 不改变 v2.2 的 pipeline 流程。数据采集作为**独立前置步骤**运行：

```
原有流程（保留）              新增采集流程
───────────────              ──────────────
15:30 trade_result.py
15:35 market_push.py  ──→    行情写入 Parquet（自动触发）
                             检查 data_collector.py --freq daily
                             ──→ 宏观日频指标自动更新

每月首日（Windows 任务计划触发）
                             python data_collector.py --freq monthly
                             ──→ 财务 + 元数据 + 宏观月频更新
```

关键原则：**采集和推送解耦**。
- `market_push.py` 继续负责行情下载和 POST 服务器
- `data_collector.py` 独立负责本地 Parquet 存储
- `market_push.py` 内部调用 collector 的行情写入函数
