# Hydra 4.8 小资金实盘监控与执行影子账本规范

## 目的与边界

本规范用于验证约 ¥200,000 的真实执行能否忠实承载 Hydra 4.8；优先解释执行偏差，
而不是以短期收益判断策略。它不改变策略权重、不生成额外委托、不读取或写入账户。

- 模型价格唯一来源：QMT HFQ；用于风险平价计算。
- 交易与账本价格来源：QMT raw；不得用 HFQ 比较成交价或记账。
- 可执行标的：9 只 ETF。`511010.SH` 只允许作为 HFQ 的 research-only 历史桥接，
  不得出现于 allowlist、target、影子订单或真实订单。
- 真实订单终态以 QMT 在 T 日 15:10 的 `trade result` 为准；活动、缺失或未知订单
  不得伪记为撤单。

## 三层可比账本

```text
QMT HFQ → Hydra 4.8 target → 执行影子账本 → 实盘账本
   策略层          可执行理论结果          QMT 实际回报
```

| 层级 | 输入 | 输出 | 用途 |
|---|---|---|---|
| 策略层 | 冻结 QMT HFQ、交易日历 | 9 个 target 权重、风险预算 | 验证模型信号与权重 |
| 执行影子账本 | target、QMT raw、公司行动、冻结执行规则 | 模拟订单、成交、持仓、现金、NAV | 量化整手/费用/现金约束造成的结构性偏差 |
| 实盘账本 | QMT 成交回报、资金与持仓快照 | 真实订单、成交、持仓、现金、NAV | 量化市场实际执行偏差 |

执行影子账本必须使用与正式执行相同的冻结规则：100 份整手、手续费、技术现金校验、
未成交处理、公司行动与价格口径。它不使用账户信息，也不替实盘下单。

## P0：每次调仓必须核验

| 指标 | 计算/口径 | 对照 | 处理 |
|---|---|---|---|
| target 完整性 | 9 个可执行 ETF、非负、权重和为 1、hash 与 sidecar 一致 | target / sidecar | 不符即禁止执行 |
| 成交价格偏差 | 实盘成交均价 − QMT raw 订单参考价；同时记录相对限价距离 | 实盘 / raw | 区分买卖方向，禁止与 HFQ 比较 |
| 影子与实盘成交差 | 成交价、成交数量、订单状态、成交时点逐笔比较 | 影子 / 实盘 | 标记滑点、部分成交、废单、延迟 |
| 可实现权重偏离 | 每只权重差、最大单项绝对偏离、组合 L1 偏离 | target / 影子 / 实盘 | 分别保存三层数值 |
| 现金残余 | 实际现金 − 策略现金目标（固定为 0） | 影子 / 实盘 | 单列整手、费用、价格保护导致的技术现金 |
| 三层 NAV 差 | 实盘−影子、影子−策略层 | 三层账本 | 不允许只报总差异，必须归因 |
| 账实一致 | QMT 资金、总持仓、可卖持仓、成交与本地账本 | QMT / 实盘 | 不一致时禁止后续执行 |

## P1：验证风险平价是否被小资金扭曲

使用 Hydra 当前实际采用的同一收益口径、回看窗口、协方差估计与权重算法；不得另选一套
相关性口径。每次生成 target 均对策略层、影子层和实盘层分别计算：

1. 9×9 收益相关性矩阵与协方差矩阵；
2. 各 ETF 年化波动率、边际风险贡献和风险贡献占比；
3. 组合预测波动率；
4. 协方差矩阵条件数及相关性/波动率的突变；
5. 理论 target、整手可实现组合和实际成交组合之间的风险贡献差异。

重点不在“相关性是否高”，而在高相关、低波动或矩阵不稳定是否让某 ETF 获得不合理的
风险贡献或权重。

## P2：交易摩擦与数据质量

| 指标 | 内容 | 频率 |
|---|---|---|
| 滑点 | 实盘相对 raw 参考价、影子价、限价的方向化 bp；成交是否贴近 50bp 保护边界 | 每笔、每日汇总 |
| 换手与费用 | 策略、影子、实盘的金额/权重换手；预估与实际费用 | 每次调仓、月度 |
| ETF 微观结构 | 买卖价差、成交额、IOPV、折溢价、停牌或无有效价格 | 下单前、日终 |
| 数据血缘 | HFQ/raw/公司行动/日历的 as_of、行数、SHA-256、producer commit | 每次发布 |
| 公司行动 | 分红、拆分/合并、份额变化、现金入账日与账本影响 | 事件发生日 |
| 独立源差异 | QMT raw 与独立价格源的差异；HFQ 收益差异仅作监测 | 月度与事件日 |

## 固定运行节奏

| 时点 | 影子账本与监控动作 |
|---|---|
| T 18:00 | 固化 target、sidecar、输入 hash；创建同一 `rebalance_id` 的影子调仓意图 |
| T+1 09:10 | 保存 QMT raw 参考价、影子订单与实盘订单意图；执行前账实核验 |
| T 15:10 | 以 QMT trade result 更新实盘订单终态；逐笔比较实盘与影子 |
| T 15:30 | 用日终 raw、公司行动更新影子 NAV 与实盘 NAV；完成三层差异归因 |
| T 16:00 | 若有残余，仅将权威未成交状态纳入下一次影子/实盘补单计算 |
| T 18:00 | 输出不可变日报与审计包；月末同时输出相关性、风险贡献和三层跟踪误差报告 |

## 必须输出的不可变记录

按 `rebalance_id`、`attempt_number`、日期和输入 hash 关联，至少保存：

- `strategy_target_snapshot`：target、sidecar、模型输入 hash、策略版本；
- `shadow_orders`、`shadow_fills`、`shadow_holdings`、`shadow_cash`、`shadow_nav`；
- `live_orders`、`live_fills`、`live_holdings`、`live_cash`、`live_nav`；
- `tracking_error_attribution`：整手取整、技术现金、费用、滑点、部分/未成交、公司行动、
  价格缺失；
- `risk_snapshot`：三层权重、相关性、协方差、波动率、风险贡献与矩阵稳定性指标；
- QMT 回报、数据包 manifest 与完整 SHA-256。

## 上线初期的判读原则

前 3–6 次月度调仓只做观察、归因与复盘，不用未经验证的静态业务阈值自动停机。唯一可
自动阻断的仍是既定硬约束：不可超可用现金、不可超可卖持仓、限价偏移不可超过 50bp，
以及 target/数据血缘/账实一致性失败。

验证结论应回答：在当前资金规模下，影子层相对策略层的偏差是否稳定可解释；实盘层相对
影子层的偏差是否由可解释的市场执行因素造成；若不是，则不得用收益表现掩盖执行或数据问题。

## 隔离联调冒烟脚本

`server/scripts/run_hydra_mock_smoke.py` 是 server/client 合约的隔离冒烟器。它只接受
已冻结的四包，创建临时 SQLite、虚拟 paper 账户与 `mock_qmt`，不会导入 `xtquant`、连接
MiniQMT 或访问真实账户。它覆盖全部成交、部分成交、即时拒单与活动/未知订单的 fail-closed
保护；每次输出目录必须是新的。

```powershell
python server/scripts/run_hydra_mock_smoke.py `
  --snapshot C:\parttime\data\hydra_snapshots\20260828-smoke `
  --output C:\parttime\data\hydra_smoke\20260828 `
  --as-of 20260828 --execution-date 20260831
```

它使用 `TEST_ONLY` 的等权 9 ETF basket 来验证 server/client 接口，不生成或冒充正式
Hydra target。正式月末 target、执行影子账本和真实账户预检仍须按运行单独立执行。
