ONE CORE · THREE WORLDS

三种盘。
不是三套互相打架的系统。

业务核心可以相同；钱的真假、成交的来源和写入的权限，必须分开。

三个盘共享

数据口径 · 策略协议 · 资金归属 · 状态与恢复 · 净值计算

不同的“执行插头”，接入同一套可验证的业务规则。Shadow 没有通向真实柜台的插头。

谁计算，谁执行，谁记账？

服务器不是一个做所有事的大进程。Windows 也不重新决定策略。

自动运行，靠的是状态，不是赌时间。

定时任务负责叫醒；前一步的证据齐了，工作流才继续。

特别提醒

撤单与下单时间必须遵守实际券商、市场、品种和订单类型的政策。这里的“晚间 / 次日 / 收尾”是工作顺序，不是已确认的现网任务时间表。

RESILIENCE BY DESIGN

遇到问题，
系统不必一起停下来。

真正的稳健，是知道受影响的是一张单、一份额度，还是整个物理账户。

不是无条件放行

可信事实要保留，不代表立即相信其归属或允许花钱。当影响无法隔离，确实需要暂停该账户新增风险；但回报、核对和恢复通道仍需保留。

26 BOUNDARIES · NOT 26 SWITCHES

闸门要守边界，
不是给整台服务器踩刹车。

每项都说清楚：在防什么、只挡哪里、什么继续、怎样恢复。点开可以逐条讨论。

MAKE THE TRADE-OFFS VISIBLE

把取舍摆在桌面上，
一起决定怎么运行。
