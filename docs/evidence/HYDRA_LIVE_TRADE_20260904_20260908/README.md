## 文件结构

- `target/`：Hydra 研究产物、九资产目标权重、目标请求、资金预检和发布回执。
- `server/orders.json`：使用 live 最小权限接口重新拉取的原始订单响应。
- `server/strategy-ledger-current.json`：采集时的策略子账本；这是当前状态，不是
  2026-09-04 收盘重建值。
- `local/state_rows.json`：与该批次相关的本地订单、提交、风控和 preflight 记录。
- 本地完整包另存有一致性 SQLite 快照；公开分支不上传该私有二进制数据库。
- `qmt/historical_log_extraction.json`：从 MiniQMT 当日日志脱敏提取的委托时间线、
  逐笔成交、持仓变化和资金变化。
- 2026-09-11 的全账户 QMT 当前快照只保存在本地完整包中；公开分支不上传账户内
  与 Hydra 无关的持仓。
- `qmt/manual-residual-20260908.json`：三笔手工补单的委托、成交、当日完整可用资金
  变化序列、关键资金检查点和持仓增量。
- `reconciliation/order_lifecycle.csv`：每个目标资产从目标权重、策略参考价、限价、
  到达价、QMT 委托号、最终成交数量和成交均价的一行式核对表。
- `reconciliation/complete_order_lifecycle.csv`：把 9 月 8 日手工补单并入后的最终核对表；
  同时保留原策略参考价、首次限价、手工限价和最终成交价。
- `provenance/code-and-data-lineage.json`：研究发布、目标、批次、attempt、客户端版本、
  热修提交以及两份 QMT 原始日志的 SHA 血缘。
- `provenance/windows-hotfix-1daf-to-ff810.patch`：交易后 Windows 兼容热修的实际代码差异。
- `historical-evidence/`：9 月 4 日当时已保存的状态检查、撤单诊断和运行日志。
- `manifest.json`、`manifest.sha256`：包内文件大小和 SHA-256 清单。

## 必须注意的口径

1. QMT 当前接口在 2026-09-11 已不再返回 2026-09-04 的历史委托和成交，因此历史
   券商事实来自 MiniQMT 当日日志；原始日志的 SHA-256 已记录。
2. 原始 MiniQMT 日志含明文敏感账户字段，所以没有复制进证据包。包内只保存脱敏、
   结构化字段；可用记录的 SHA-256 回到原文件复核。
3. MiniQMT 日志的 `commission` 字段在这些成交上均为 0，这只能表示该日志字段没有
   给出最终费用，不能据此认定券商实际手续费为 0。最终手续费应以券商交割单为准。
4. `qmt_read_only_export.json` 的资金和持仓是 2026-09-11 当前快照；9 月 4 日盘中资金
   变化和成交持仓变化见 `historical_log_extraction.json`。
5. live API key 按最小权限设计，不能读取 `/admin/orders` 和 `/admin/trades`。403 回执
   已保存在 `server/admin-*-access.json`，不是采集失败。
6. Server 当前仍能通过 `/orders?date=20260904` 返回 9 笔订单，而策略子账本没有反映
   这 6 笔成交。这是待核对差异，证据包没有擅自修正它。
7. 9 月 8 日补单前可用资金为 318,939.55 元，收盘前最后观测为 306,173.55 元，减少
   12,766.00 元；三笔成交金额为 12,751.00 元，差额 15.00 元与三笔各 5 元最低佣金
   相符，但在取得券商交割单前仍标记为“推断手续费”。
