## 二 与 Hydra 的差异和需要回报的问题

1. **现金预留 1%。**Hydra 是 0%。股票腿按 V713 原规则在腿内留 1%，合成账本不再另留，避免重复预留。请业务侧确认。
2. **不设 ETF 特殊买入带。**按确认记录第四节，不套用黄金、纳指等 ETF 的 100 / 150bp。
3. **科创板卖出最小申报量（上线前必须补）。**交易所规则是：科创板卖出申报不少于 200 股，余额不足 200 股时须一次性卖出。现有 `InstrumentSpec` 没有最小卖出量字段；当股票腿对持续持有的科创板股票做部分减仓，且减仓量不足 200 股时，计划会生成一笔会被交易所拒绝的委托。清仓和退出名单时都是全部卖出，合法。拒单不会造成错误成交，但会留下超配。修复需要服务器与 Windows 客户端同时升级证券规格，不在本次改动内。
4. **过户费 0.001%。**按法定费率写入；确认记录写明“印花税等其他交易费用另计”，需要用真实账单核对。如券商已把过户费包含在佣金内，改为 0。
5. **虚拟切换成本 20bp。**只存在于合成规则文件 `synthetic_policy_v1.json` 的 `primary_bps`，另报 0bp、50bp。确认记录指出它尚未单独获批；改动只需改文件，不需改代码。
6. **旧规模实验的费率。**`reports/v713_scale_share_delta_20261023/` 使用万 2 加最低 5 元，没有按万 0.854 重跑，不能引用为新费率下的结果。
7. **周五和节前不做卖出日。**这是 Hydra 流程固有的约束：卖出日的下一自然日必须开市。月初执行会顺延到下一对相邻交易日。

## 三 真实 Hydra 收益来源与版本身份

- 来源：合成账本读取 Hydra 实例 `live_hydra_v481_rb` 的每日 `PerfSnapshot.daily_return`。该值由 attributed 实盘账本按不复权收盘价估值，并按 `CashFlowJournal` 剔除资金进出。
- 版本：采用含 `511260.SH` 的现行 Hydra。部署回执需要记录 Hydra 实例当时运行的 release 和目标来源哈希；合成输出中记录了 Hydra 实例 ID。
