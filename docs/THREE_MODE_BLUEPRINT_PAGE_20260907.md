## 这次交付是什么

这是给懂经营和金融规则、不需要读代码的同伴使用的架构讨论页。已接入本地 Dashboard 与旧系统审阅页的导航，保留旧审阅，不覆盖历史讨论。

**本次交付的是网页及设计规范，不是新交易核心上线。** 页面所说的完整资源授权、事实接收、三盘统一账务等，仍是拟议架构；每项闸门另外标明当前实现和差距。示例资金不是当前真实余额。

首版先完成本机预览与验收；用户随后批准将该页面发布到 server Dashboard。页面发布不修改 Windows 任务、私有配置或生产交易开关，不连接真实 QMT，不生成、提交或撤回真实订单。精确发布版本、上线结果以发布回执为准，不能把本机预览链接当成同伴可以远程访问的正式地址。

## 建议用 10 分钟这样讲

1. 先看“三个盘，一套规则”：影子盘的事实来自模型，模拟盘来自模拟柜台，实盘来自真实柜台。共用业务规则，不共用资金、凭据和事实。
2. 回到“一笔钱的旅程”，播放或逐步前进。总资金池 1,921.1 万，只划 21.1 万给 Hydra，另外 1,900 万不属于它。
3. 停在“晚间授权”。现金仍是 211,000，其中 100,050 已承诺给执行包；预留不是亏损，也不能被其他策略再次领取。
4. 选择“早上 server 断线”。本地有有效包就能完成授权范围内的执行，事实暂存在本地；不能把本地成功说成服务器已经入账。点击演示恢复，续传事实而非再下一遍单。
5. 选择“只成 400 份，余单仍已报”。已成部分照常记账，余单仍可能成交时不重复补。演示拿到已撤证据后，释放余款，再由服务器计算剩余 600 份。
6. 选择“晚间又到账 100 万”与“持仓跌 2%”。无关入金不增加 Hydra 预算，亏损也不自动从储备补回。
7. 在“闸门与预案”搜索 G07、G09、G14、G21。分别讨论入金、资金重复承诺、早上不依赖服务器、响应丢失后取回原结果。
8. 打开“取舍与讨论”逐项记录意见。最后导出讲解与纪要，把未决问题和负责人交给同伴。

所有“演示恢复”按钮只注入教学证据，不检测或操作真实环境。“同意方案”不构成交易批准。

## 画出来后，对架构的复核

本次同步把规范升级为 v1.1，重点补清第 7.3 节的协调器锁边界；另用金额演示和讨论项校验下列已有原则。

1. **单账户单写者，不是一张单占住整天。** 短事务认领；等待成交让出调度；撤单与未知意图恢复优先。外部调用本身卡住时不能保证中断，更不能另启执行器盲目重发。
2. **预留是用途承诺，不是资金损失。** 服务器预留、本地认领、券商冻结关联同一资源，不能重复扣减。与当前券商快照尚未反映的在途占用分清。
3. **离线可执行和即时远程撤销不能同时无条件承诺。** server 停新计划不等于本地已停。既有授权需明确交回或核实旧执行器失去写能力，才可重新分配。
4. **可信入金自动核实，不是每次人工开闸。** 接收事实、确认归属、分配策略资本是三个动作。旧订单不应阻断新到账，但未知来源不直接增加购买力。
5. **交易结案与财务最终化分开。** 数量与归属清楚、费用上界有依据且留足准备金时，可先交易结案；未知成交数量不能冒充“小额费用差”。
6. **待认领不是藏差额的桶。** 每项需要来源、影响资源、处理人及升级期限。不能证明影响可隔离时，确实应暂停该物理账户新增风险，保留事实接收和恢复。

## 讨论如何保存

- 默认阅读、播放、筛选和全部演示均不需要凭据，也不连接讨论数据库。
- 本地草稿存储键为 `hydra_blueprint_notes_v1`，只在当前浏览器；不会自动上传。导出包括已保存意见，不包括还没保存的输入。
- 共享会话为 `three-books-blueprint-20260907-v1`，与旧审阅会话隔离。复用现有 review 表，无新增 schema 迁移。
- 共享接口仅使用 `/admin/architecture-blueprint/session`、`comments`、`decisions/{id}`；沿用现有管理/审阅身份校验，没有扩展 live key 的交易白名单。
- 连接凭据只放当前页面内存，不进入 localStorage、链接或自动导出；主动断开或页面离开清除。
- 页面按钮不能调用资金、订单、撤单、策略发布接口。连接失败时仍可阅读、演示和保存本地草稿。
