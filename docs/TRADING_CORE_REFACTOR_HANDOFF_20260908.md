# 三盘交易内核重构：规则确认与第一阶段交接

日期：2026-09-08。基座：本地 `72b4a9b`。

**这是本地代码与测试交接，不是现网已部署公告，也不是开始交易的授权。** 本轮未访问真实 QMT、未调用服务器资金/订单写接口、未切换 Windows 任务。线上 blueprint 仍是上一版讨论页，不能据其画面判断这些代码已经上线。

## 1. 本轮经营规则

### 三个盘的共同规则和不同事实来源

| 项目 | 研究/影子盘 | 模拟盘 | 实盘 |
|---|---|---|---|
| 钱从哪里来 | 明确的假设本金及仿真现金流 | 模拟账户资金及其归属 | 券商实际现金事件及其归属 |
| 持仓由什么更新 | 仿真成交规则 | 模拟执行回报 | QMT / 券商成交与交割证据 |
| 策略可用资金 | 本策略资本及本策略盈亏 | 本策略资本及本策略盈亏 | 本策略资本及本策略盈亏，且受 QMT 实际可用资金约束 |
| 到期意味着什么 | 按声明的仿真规则结束 | 按模拟执行器规则结束 | 本轮结束；不能仅靠墙上时钟捏造券商终态 |
| 对其他盘的影响 | 不修改另两盘 | 不修改实盘/影子账 | 不覆盖影子或模拟假设 |

目标架构共享的是现金事件、归属、目标、订单生命周期和收益口径，不是共用一个账户余额或把三种成交来源混成一张账。**本轮是接入现有系统的第一刀，尚未将影子/模拟的全部旧写路径迁到同一个内核。**

### 一笔钱的处理顺序

券商发生收支 → 先留存事实 → 识别归属 → 记策略增资/减资等分录 → 下一份未冻结目标使用新额度 → 离线执行 → 成交更新本策略钱和持仓 → 资金变化剔除后计算收益。

“钱已进入券商账户”不需要服务器重新批准。它也不等于“这笔钱已全部属于 Hydra”。同账户暂存的其余资金不自动成为 Hydra 的本金或收益。

## 3. Close 的具体含义

### 到期 Close：结束本轮工作流

现有 `POST /hydra/attempts/close` 新增向后兼容的显式模式：

```json
{
  "execution_domain": "live",
  "account_alias": "YOUR_ACCOUNT_ALIAS",
  "attempt_id": "EXISTING_ATTEMPT_ID",
  "close_mode": "execution_deadline",
  "execution_deadline_at": "2026-09-08T15:00:00+08:00",
  "reconciliation_evidence_sha256": "64-character-hash-of-workflow-intent"
}
```

这是契约示意，**不是可直接执行的命令，也没有规定所有产品必须 15:00 到期**。截止时间应来自该批次的执行安排；服务端校验带时区、属于 attempt 的交易日且已经到时。此模式不要求 QMT 在线，不要求当场提供现金/持仓；沿用的 evidence 字段在此模式中表示工作流意图证据，不冒充券商清算证据。

- 仍有未决订单：`CLOSED_PENDING_BROKER`。
- 订单已有明确结束结果，但财务尚未核实：`CLOSED_PENDING_RECONCILIATION`。
- 两者均正常返回“工作流已关闭”；不生成可执行 residual，不改写 `Order.status`，不释放未决义务。
- 新表 `hydra_workflow_closures` 留存请求和原始回执；同请求重放不会再建单或记钱。
- 本地新增 `close-window` 命令及 Windows runner 参数入口；先持久化关闭意图，再通知服务器。服务器临时不可用时，已关闭的本地窗口也不能重新发单。现有计划任务没有自动切换到该命令。
- 已到期关闭的批次不再从普通拉单队列交付。**这不是远程撤销已经下载到本地的委托包**，本地也必须遵守执行截止时间/关闭标记。

### 最终 Close：确认可以补多少

省略 `close_mode` 的旧请求仍是 `broker_final`：收取实际回报，对齐归属账，再计算原目标和实际持仓的差额，返回 `COMPLETE` 或 `RESIDUAL`。关闭“生成新订单”不会再阻止这一收尾路径。

`settle` 已改为分别接回可独立验证的回报：一笔仍“已报”不会丢掉另一笔已成交事实。还有待核实订单时，`settle-close` 返回 `WAITING_FOR_BROKER`；Windows 日终通知明确说仍有待核实项，不再把它描述成程序崩溃或最终结案成功。后续观测/队列唤醒的正式调度仍需部署接线，不能以任务退出成功替代最终财务状态。

真实 SDK 中“部撤”与“部成待成交”不是同一状态：本轮客户端将 QMT 53 映射为 `CANCELLED + 已成交数量`，55 的成交部分单独作为进行中的成交事实。服务器允许同一累计成交从 PARTIAL 变成 CANCELLED，但不重复扣款/加仓。来源：[迅投 XtQuant 交易模块官方文档](https://dict.thinktrader.net/nativeApi/xttrader.html)。

你们观察到该券商会长时间保留“已报”，这一情况必须支持；但它不能推导出所有券商都没有废单或撤单查询。**正式解除这些旧单占用，需要接入券商规定的委托有效期及清算后查询证据。** 到期 Close 先解除“日终任务一直失败”的耦合，不假装这份证据适配已经完成。

## 4. 策略资金：增减而非重设

新增两个用途不同的入口：

- `POST /accounts/cash-observations`：已发生的账户现金事实。没有策略也收下，出现负余额也保留；返回 `RECORDED_UNALLOCATED`，不悄悄改策略现金。
- `POST /accounts/capital-movements`：对一个已初始化子账本执行 `INCREASE` 或 `DECREASE`，金额永远正数，方向单独声明。不改原始本金、持仓或冻结订单。

增资应使用新鲜的 QMT 总现金（包括冻结现金）和已收到事实的水位，不能拿昨天的资金快照作今天的新额度。实际下单则看 QMT 可用现金。两个口径不能混用。金额分录与请求回执同一短事务落库；网络丢回执可以重放，不重复划钱。

完整契约、已有调用兼容和限制见 [策略增减资部署与迁移](STRATEGY_CAPITAL_MOVEMENTS_MIGRATION_20260908.md)。账户事实记录与策略资本命令不能两次算成策略本金。当前增减资只影响下一份未冻结目标，不自动扩大既有 residual 订单。

### 什么时候可以增资

已经初始化、归属明确且能证明未分配资金来源时，可以登记一笔明确金额的增资；不用等待账户里每个策略都没有订单。它不会扩大已经交付的订单包。若想立即使用新钱，需要后续明确的“新资本重平衡”流程，而不是偷偷修改旧单。

逐步放大应依据同证券、同方向、相近流动性和时段的真实执行数据，同时观察未成交率、成交耗时和费用。没有“运行几天即可自动扩容”的硬编码闸门或承诺。参见 [执行质量与逐步增减资](HYDRA_EXECUTION_QUALITY_SCALING_20260908.md)。

## 5. 鲁棒性和可扩展性边界

本轮将资本命令、兼容现金流写入、成交回报、Hydra stage/close 接到先读后写的短事务边界；SQLite 使用 `BEGIN IMMEDIATE`，不在事务里等 QMT 成交。相关 HTTP 处理改为线程池同步入口，减少同步数据库/数据文件工作阻塞主事件循环。

这不是整个系统已经完成账户级单写者改造：初始化、旧管线、运维恢复脚本等尚需逐一迁移；非 SQLite 的独立账户锁行、跨主机执行、离线额度发放/归还和同标的多策略资源共享还需要后续实现与压测。现有浮点存储也尚未整体换成整数金额/高精度双分录总账。

代码可以按兼容性回退，**已经发生的交易和资金历史不能跟着回退**。本轮没有新增“一有异常就关整台服务器”的启动检查，也不把通知失败、滑点样本不足当成资金事实拒收理由。

## 6. 部署顺序与验收边界

1. 先审查本地改动和契约，使用副本数据库验证新增三张表：`account_cash_observations`、`capital_movement_receipts`、`hydra_workflow_closures`。不改已有表列、不清交易历史。
2. 用假 QMT/隔离服务验证：入金与生成开关无关；增资不算盈利；减资不碰旧单占用；旧单到期关闭不伪造废单；部分成交转部撤不重复入账；卖款未到账时只暂缓买单。
3. 服务器先具备新 API 和 `NOT_SUBMITTED` 状态支持，再部署兼容的客户端。新状态表示该单因资金不足确实没有进入券商调用，不是券商废单，也不能替代“提交结果未知”。
4. Windows 先验安装器、任务入口、QMT 查询字段及实际费用政策，再接线新 Close 与队列唤醒。当前已有 `settle-close` 不应被误认为自动采用了到期 Close。
5. 只读复核当前券商的有效期/清算规则和残余订单；接受生产演练后再切任务。当前文档不是“立即覆盖现网”的操作授权。

本地验证命令：

```bash
# 在 v2.3/server
venv/bin/python -m pytest tests -q -ra -o addopts=''
# 在 v2.3
server/venv/bin/python -m pytest live_client/tests -q -ra -o addopts=''
```

这些测试不等同于 Windows + 券商真实验收。真实策略 bundle 缺失的测试要明确报告跳过，不把它写成实盘全链路通过。
