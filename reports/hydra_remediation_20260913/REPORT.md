## 1. Server 到底在干什么

可以把整个系统理解成三种不同职责：

| 位置 | 它负责什么 | 它不应做什么 |
|---|---|---|
| 服务器 | 收数据，计算/接收策略目标，按策略自己的资金和持仓生成订单；记录成交、现金流、归属及剩余差额 | 不能把“生成了订单”当作“已经成交”；不能把券商整个账户的钱都当成 Hydra 的钱 |
| Windows + MiniQMT 客户端 | 晚间取单、校验并保存；交易日按冻结内容下单；观察券商状态并回传 | 早上下单不再依赖服务器在线；不自行改策略目标或复制不确定是否已报的委托 |
| 券商 / QMT | 提供实际委托、成交、账户资金和持仓事实 | 账户总持仓不能直接回答“其中多少属于 Hydra，多少属于 Kobold” |

服务器内的三个盘也不是同一本账：

- 影子盘：验证目标和理论路径，不发真实订单。
- 模拟盘：跟踪模拟执行和模拟账务；模拟成交机制的偏差不能直接叫作真实市场滑点。
- 实盘：以券商实际成交记账，再通过委托来源归属到策略。目标、委托、成交、净值是四个不同阶段。

**现状正是“实盘执行已经发生，但服务器记账落后”**。因此单看 dashboard 上的现金和持仓，暂时不能得到完整的真实实盘状况。

## 5. 本轮候选代码实际修了什么

### 5.1 缺输入是可以恢复的等待，不是整台服务器失败

V53 缺分红文件或调仓所需历史不足，明确报告 `WAITING_INPUT`；其他策略照常运行。不再悄悄切换成未复权模型。晚到或替换的分红文件会重新读取，不要求重启服务器。

等待状态保留原业务日期。次日恰好“不调仓”的成功运行不会把昨日漏做的调仓标成已经恢复。补齐后仍需明确重跑原业务日期；本轮没有实现自动跨日补调仓，也没有授权用历史日期下新单。

### 5.2 没有估值价格，不等于持仓市值为零

找不到有效持仓价格时，仅跳过该策略本次 NAV 写入，标记 `WAITING_PRICE`，其他策略继续。补齐后可重算。正常策略状态不被无谓改写。

仍保留原有“最近一个可用收盘价”的估值兼容规则；未完成长期停牌/陈旧估值的分层质量标注，也未自动修复此前错误快照。

### 5.3 合入 Windows 现场兼容修复

保留同伴热修的 UTF-8、Webhook 字节编码、UTF-8 日志、旧任务别名兼容；Python stderr 的普通日志不再因 PowerShell `Stop` 直接被当作进程失败，立即保存真实退出码，再判断成功回执。

继续保留新版服务器专用 advance 流程，不回退成普通 trigger。09:10 离线 submit 不新增服务器依赖。这里只通过 Python 测试及源文件约束检查，**没有原生 Windows PowerShell 5.1 验收**。

### 5.4 多策略分红/收入归属入口

新增 `POST /accounts/income-allocations` 和增量表 `income_allocation_receipts`：

1. 先用既有 `/accounts/cash-observations` 记录真实到账事实。到账事实不要求先准备策略或订单。
2. 根据明确的归属证据，将该笔正收入全额分给一个或多个独立策略账本；金额按分校验，合计必须守恒。
3. 同一事务写各策略现金、journal 和归属回执。任一归属出错全部回滚，到账事实仍保留。
4. 同一请求重复调用复用回执，不重复加钱；同一笔钱不能改个分配比例再加一次。
5. 已归属的收入退出待归属池，但进入策略拥有的现金，所以不会突然变成可再次分配的闲钱。

不检查是否有未成交订单、是否已生成 target，也不依赖下单开关。保留的限制只有账户/执行域边界、金额守恒、策略归属和重复入账保护。未解释的收入仅暂存其自身金额，不冻结整个账户业务。

此入口不自动计算权益，不隐式增资，不直接设余额，不改已冻结批次；也不实现收入冲正或旧 journal 归属回执迁移。旧方式已经入账的同一来源事件，会明确要求迁移回执而不是再加现金。新旧调用方必须使用一致的原始现金流水身份，不能随意换 source/event_id 规避去重。

## 7. 关于是否“防御过度”

应该撤掉的是错误耦合：服务器短时离线不该挡住已准备好的本地下单；一笔未终结不该挡住其他已成交事实；缺一种模型输入不该让其他策略停摆；实际到账不该等一次新的交易授权。

应该保留的是资金含义：同一笔成交只记一次；同一笔分红只分一次；不同策略不互拿现金；缺价格不伪造净值；三点业务到期不冒充券商真实撤单。这些约束不应以“重启服务器/中断整条流水线”实现，而应把影响限于相关订单、策略或金额，并给出可恢复状态。

因此不是简单“把闸门全撤掉”，也不是“加更多闸门”；本轮重点是**把不相关的失败隔离开，并提供补数据、补记账、重复请求的正常恢复路径**。
