# Hydra 部分资金与跨日补单边缘情况验收

日期：2026-10-02。状态：代码和离线回归完成；本轮没有部署服务端或 Windows client，没有连接真实 QMT 或发送订单。

## 已实现的行为

| 情况 | 处理 |
| --- | --- |
| 9 笔买单，只够先下 6 笔 | 已冻结批次按顺序逐笔检查，先提交可负担的 6 笔，另外 3 笔标记 `DEFERRED_CASH`；不要求全部卖单成交 |
| 一笔卖单迟迟未成交 | 其他已确认卖出收入仍可用于符合条件的买单；未成交卖单的预计收入不能当作可用现金 |
| 队列排序 | 卖单先于买单；新政策买单按明确优先级、剩余订单金额从大到小、证券代码排序。优先级数字越小越先，未指定的标的排在最后一档 |
| 优先级高的大单资金不够 | 暂缓这整笔，继续检查后面可负担的订单；优先级是执行偏好，不是必须同时完成的组合约束 |
| 跨日后资金或价格变化 | 旧 attempt 完成券商最终状态核实和对账后，服务端用实际现金、持仓和新参考价格重新生成剩余订单；client 不修改冻结订单 |
| 重新生成时资金不足 | 只用本策略已到账现金，保留现金缓冲和费用。同优先级内按剩余买入金额比例缩量，整手取整，再按最大余数分配可负担的一手 |
| 原定数量偏离新权重 | 取原剩余数量与新价格下目标仓位缺口的较小者，不增加原目标之外的份额，不反向撤销已经完成的成交 |
| 一个标的超出价格界限、停牌或零成交量 | 暂缓该标的，其他符合约束的标的仍可生成订单；回执记录逐标的原因 |
| 价格越界、目标失效、补单窗口到期 | 保留当前持仓与现金；原始 50 bp 价格界限和三个交易日窗口不向后滚动 |
| 重复运行或重启 | 已提交订单不重复发送；资金到账后仅恢复确定尚未提交的订单。结果不明的委托继续沿用停止自动重发的规则 |

这里有两个不同阶段：当前冻结的九笔整单可以先执行其中六笔；下次重新生成计划时，才按比例重新分配购买量。例如九个同价标的各计划买 900 份，预算足够各买 600 份及费用时，新计划会分配九笔各 600 份，而不是先给六个标的买满。

## 实现与审计

- `v2.3/server/app/services/hydra_cash_allocation.py`：整数分预算、费用、分档比例分配、整手处理、最新仓位上限和价格约束。
- `v2.3/server/app/services/hydra_relay.py`：在现有重试生命周期中调用重新分配，保留未完成原目标，记录审计；响应订单数使用实际生成数量。
- `v2.3/server/app/schemas/hydra_relay.py`：`buy_priorities` 进入目标 hash；暂缓回执附带 `allocation_audit`。
- `v2.3/live_client/execution_queue.py`、`core.py`、`cli.py`：验证冻结政策、执行排序、继续使用实际成交和 QMT 可用现金的双重校验。
- 新批次政策为 `PROPORTIONAL_RESIDUAL_V1`，放在 `execution_policy.cash_allocation`，参与批次 hash。变更优先级会导致 hash 校验失败。
- 成功生成的补单在 `risk_snapshot.cash_allocation` 留下现金预算、费用预留、更新后的目标份额上限及逐标的暂缓原因；无可执行订单时返回同类审计，不创建空 attempt。
- 原 `target_shares` 不改写，所以缩量完成不等于原调仓目标全部完成。未满足部分仍是 residual，窗口结束后继续如实保留。
- 原来已冻结且没有新政策的批次保持原行为，不自动迁移历史批次。

## 验证结果

2026-10-02 本地执行 329 项测试，0 失败、0 错误、0 跳过，原始结果见 `tests.xml`。

覆盖 Hydra 计划生成、归属账户、跨日补单、迟到成交、紧急处置、执行域隔离，以及全部独立 live client 测试。新增重点覆盖：

1. 六笔卖出已成交 → 六笔买单提交、三笔等待 → 资金补足后只恢复三笔。
2. 一笔卖出不成交不阻塞其他八笔有资金支持的买入。
3. 明确优先级控制实际提交顺序，篡改优先级无法通过 batch hash；大单不够时仍能执行后续小单。
4. 九笔同比例缩量、资金只够六个最小交易单位、最低佣金、现金不足一手、不同价格与预算的 200 组确定性随机案例，均不透支、不扩大数量。
5. 跨日涨幅在界限内时更新数量但保留原限价；界限外不创建订单，单一标的越界不阻塞其他标的。
6. 已有成交从剩余需求扣除，停牌与未成交卖单不能虚增现金，现金缓冲得到保留。
7. 无效目标、旧批次兼容、剩余目标和审计记录、重复执行回执。

另外，在独立测试进程中临时使用旧的证券代码排序，优先级回归测试按预期失败；恢复新代码后通过。没有为此改写工作区文件。

## 上线范围与限制

本轮仅完成代码、离线测试和文档，没有更新生产服务或 Windows client。新政策要在服务端和 client 都具备对应版本后使用；老 client 对新增字段的处理不能代替这次排序实现。

这次没有实现独立的“参考日收盘卖、次日开盘买”调度器，没有接入成交回调，也没有更改现有每轮结束后等待 30 秒的查询频率。这里实现的是现有 client 队列和服务端跨日补单内的边缘情况处理，不能据此汇报完整两阶段实盘策略已上线。

测试使用合成数据和 mock QMT，没有读取或下载真实行情、账户明细，不能作为券商真实成交或到账时延的验证。价格判断使用已冻结的新参考日行情；实际执行仍受订单限价和 client 提交前资金核验约束，不保证次日成交。
